## Export and delete move into a boat settings page

**Prompt**

The same overnight prompt as [#147](https://github.com/heynewton/newton/pull/147)
(`2026-10-21-0141-boats-header.md`), which asked for #133 and then #142, one PR each, with #142
stacked on #133's branch.

**What Claude did**

- Added `/boats/<id>/settings` with the existing export section and a set-apart, red-bordered
  "Delete this boat" section (owners only), linked as "Boat settings" from the header's account
  menu for owners and co-owners. The page 404s for crew and read-only members, as the delete page
  does for non-owners. The export route and delete action didn't change.
- Removed export and delete from the boat page, so delete is no longer next to an everyday link.
- Made the delete page's "download first" sentence link to the export download.
- Updated `docs/architecture.md` and `docs/export.md`.
- Checked it on the local stack with the sample boat at three widths in light and dark, by touch
  and keyboard, as its owner, a co-owner and crew, and downloaded the export from the new link.

**What changed along the way**

- Deleting a test boat from the new settings page showed that the header's boat list went stale
  after a server action, because the layout is kept across navigations. The fix (revalidate after
  creating, a full page load after deleting) went into #147, which introduced the header.
- Chose a settings page over a bottom section of the boat page, because the new header gave it an
  obvious place and it keeps delete off the everyday page.
