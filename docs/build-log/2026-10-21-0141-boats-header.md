**What Claude did**

- Added `boats/layout.tsx`, which gives every `/boats/*` page a header: the logo back to `/boats`,
  the open boat with a switcher when the person is on two or more boats, and an account menu
  (signed in as, add a boat, sign out).
- Wrote a small disclosure `Menu` (tap, click or keyboard to open; Escape, a tap outside, tabbing
  out or navigating to close) with 44 px rows and a focus ring that shows in both themes.
- Removed the repeated links and sign-out from the bottom of the boat page, `/boats` and
  `/boats/new`. Owners' "Delete this boat" stays at the bottom of the boat page until #142.
- Checked it on the local Supabase stack with the sample boat, driven by Playwright at three widths
  in light and dark, by touch and by keyboard, as the owner (with a second fake boat added to
  try the switcher) and as crew.

**What changed along the way**

- A layout doesn't receive its child segments' params, so the switcher reads the open boat with
  `useParams()` on the client, and the server passes it the person's boats.
- The shared class string for menu rows first lived in the client `menu.tsx`. A server component
  importing a string from a `"use client"` module gets a reference, not the string, so it moved
  to `menu-item.ts`.
- The boat page keeps its own logo above the name for now: #134 is editing that block in a
  parallel session, and removing it is a one-line follow-up.
- The container had Node 22 and the repo requires 24, so Node 24 ran from a local download. Docker
  also had to be started by hand before `supabase start`.
