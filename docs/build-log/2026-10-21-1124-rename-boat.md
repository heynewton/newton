## Owners can rename their boat in boat settings

**Prompt**

````text
Allow owner to rename boat in boat settings (https://heynewton.app/boats/[boat ID]/settings)
````

**What Claude did**

- Found no issue for it, so opened #158 (`web`, Phase 1) with a "Done when" list.
- Added `renameBoat()` to the web app's data layer and a "Name" section to boat settings, shown
  to owners only, with a server action that revalidates the root layout so the header's boat
  list picks up the new name.
- Added 13 unit tests for `renameBoat()`.

**What changed along the way**

- No migration was needed: row-level security already lets owners and co-owners update
  `boats.name`. The prompt said owner, so the app checks for owner and the PR asks whether
  co-owners should rename too.
- A boat being deleted can't be renamed, and the field notes that the boat's email address
  doesn't change with the name.
- The container had Node 22 (the repo asks for 24) and no Docker daemon, so checks ran with
  `npm ci --engine-strict=false` and the change was checked on the Vercel preview instead of a
  local Supabase stack.
