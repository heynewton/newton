**What Claude did**

- Checked Node's release schedule: v24 was Active LTS until 2026-10-20 and v26 becomes Active LTS on 2026-10-28. Vercel only offers 24.x and 22.x, so Claude picked **24**: the newest LTS that runs everywhere. Next.js 16, supabase-js, vitest, eslint and TypeScript all support it.
- Set `.nvmrc` to `24` and `engines.node` to `"24.x"`, in the root `package.json` and in `apps/web/package.json`. The second is needed because Vercel's Root Directory is `apps/web`, so `vercel build` reads `engines` there, and `engines` overrides the project's Node setting.
- Added `.npmrc` with `engine-strict=true`. On Node 18 and 22, `npm install` now stops with `EBADENGINE … Required: {"node":"24.x"}`.
- Moved `@types/node` to `^24` in every workspace and added it at the root, so vitest and vite's optional peer stops pulling in `@types/node@26`. The lockfile went from three versions (20, 22, 26) to one.
- Confirmed every workflow reads `.nvmrc` and nothing hard-codes a Node version. README "Development" explains `nvm install` / `nvm use`.
- Installed Node 24 with nvm and ran `npm ci`, `npm run check` and `npm run build` on it: all pass.

**What changed along the way**

- The first build failed fetching a Google font; a retry passed, so it was the network, not Node 24.
- Vercel reading `engines` from `apps/web` rather than the repo root wasn't in the task; Claude found it in the Deploy workflow's Root Directory setting.
